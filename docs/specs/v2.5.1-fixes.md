## Problem / goal
The 2026-10-04 code review found 2 tracked issues (F1, F2) and 7 new bugs (N1–N7) in `extension/content.js`. Two of them can harm a live call: F1 can click Meet controls without a safety check, and N3 can click the People button when it shouldn't. Two others silently give wrong results: N1 shrinks the roster in large calls, and N2 leaks one meeting's names into the next.

**Goal:** fix all nine without changing any feature that already works. Every fix starts with a test that fails on v2.5.0, plus a mutant in `scripts/mutants.json` that re-introduces the bug (GRH-053).

## Non-goals
- Accessibility (keyboard Bingo, `aria-live` toasts, focus keeping), deck repeats after reshuffle, Ask during the pick animation, and storage expiry. These are deferred to **v2.6** specs (`bingo.md`, `speaker-picker.md`, `storage.md`). They're listed under "Deferred" below so they aren't lost.
- Moving storage to `browser.storage.local` (F3). That's Phase 3, ADR-0002.
- Any change to content, UI copy or layout except the toasts named below.

## Behaviour

### Safety: clicks into Meet (GR-2)
| ID | Requirement | Acceptance criteria | Test level |
|----|---|---|---|
| SAFE-001 | MUST route every click into Meet's DOM through a single function `safeClick(el, reason)`. It re-checks `safeCandidate(el)` (visible; not a switch/checkbox/menuitemcheckbox; no `aria-checked`; label not unsafe), refuses elements that are no longer connected (`!el.isConnected`), logs `reason`, and returns `true`/`false`. `.click()` appears exactly once in `content.js`, inside `safeClick`. *(v1.2: `aria-pressed` is **not** refused, because Meet's real People button is a toggle that carries `aria-pressed`; refusing it would stop sync in real calls. Toggles stay blocked by role, `aria-checked` and the label check.)* | The suppression ledger shrinks to **one** `G1-REVIEWED` entry. Guard fails if a second click site appears or `safeClick` stops checking `isConnected`/`safeCandidate` | guard + lint |
| SAFE-002 | MUST fix F1: expanding collapsed groups clicks only `[aria-expanded="false"]` elements that are (a) **inside** the participants list, not its parent, (b) pass `safeClick()`, and (c) have a label or text matching a group-header pattern (`/contributors\|in the meeting\|in call\|participants\|others\|guests/i`) | Given the trap page (GRH-031) with `aria-expanded="false"` toggles next to and inside the list, when a full sync runs, then only the "Contributors" group header is clicked. The `KNOWN-F1` ledger entry is deleted, and guard no longer warns about F1 | e2e (safety) |
| SAFE-003 | MUST fix N3: the undo step after a sync (a) looks up the People button again with `peopleButton()`, (b) clicks it only if the People list **we opened** is still showing (`participantsList()` is visible), and (c) never clicks if another panel (Chat, Activities) has replaced it. If it can't undo safely, it doesn't click, sets `syncPaused`, and logs why | Case 1: the host opens Chat during a sync → no undo click, Chat stays open. Case 2: Meet re-renders the toolbar during a sync → the new button is used and the panel ends closed. Case 3: normal sync → the panel ends closed (as today) | e2e |
| SAFE-004 | MUST make `UNSAFE_LABEL` match plurals and verb forms of every unsafe word (`options`, `messages`, `mutes`, `muted`, `removes`, `locks` …) by allowing an optional `s`/`es`/`ed`/`ing` ending, and the guard checks the plural of each required word | Given a button labelled "Meeting options" or "More options" with a `group`/`people` icon, then Diagnose's `peopleButton` is `null` (SAFE-TABLE rows). ## UI: states and copy
- New toast (SAFE-003, when the undo is skipped): **"Sync paused: Meet's side panel changed. Tap sync again when the People panel is closed."** Shown only for manual syncs (`!silent`).
- New toast (SYNC-001, panel open but incomplete, manual sync only): **"Synced {n} so far. Scroll the People panel to the bottom or tap sync again."**
- No other visible changes.

## Edge cases
- **Meet's headcount is wrong or missing** (SYNC-001): when `peopleCount()` is `null`, reaching the bottom alone makes the scan complete.
- **The user scrolls the People panel themselves** during a sync: the loop restores `scrollTop` to where the user left it, not to 0.
- **"You" row:** your own name may appear as "Rutvik Bharat (You)" in the list but not in the headcount. That's why the threshold is headcount − 1.
- **Breakout rooms / `/lookup/` URLs** (ROSTER-001/002): the meeting code changes when you move into a breakout. Each breakout gets its own roster.
- **Two Meet tabs in the same browser**: they share `localStorage`. Each tab writes only its own meeting's keys, so they don't collide. (F3 later makes this safer.)
- **Non-English Meet UI** (DIAG-001, SAFE-002): labels the vocabulary doesn't recognise become `…`. That's acceptable: Diagnose still reports structure.

## Safety / privacy notes
- After SAFE-001 there's exactly one place in the code that clicks Meet's DOM. Any future click must go through `safeClick()` and come with a trap-page test (GUARDRAILS §6).
- DIAG-001 means a user can paste a Diagnose report into an issue or a chat with an AI without exposing colleagues' names or the meeting link.
- ROSTER-002 stops participant names from being written under a shared `home` key.

## Decisions (were open questions)
1. **F2:** passive expiry is **90 s** (`PASSIVE_EXPIRY_MS = 90000`).
2. **SYNC-001 threshold:** headcount − 1. Revisit after a real-call Diagnose report from a call with more than 15 people.
3. **SAFE-002 labels:** English only for now. Hindi labels will be added when a Hindi-UI Diagnose report is available.
